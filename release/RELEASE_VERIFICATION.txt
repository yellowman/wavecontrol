ENVIRONMENTAL LIMITATIONS (NOT CLAIMED AS PASSES)

  The Makefile was exercised with GNU make, constrained to the documented
  common subset, checked against the official OpenBSD make/install manuals,
  used to stage a complete OpenBSD root, and used to cross-build OpenBSD
  amd64/arm64 executables. A native OpenBSD `make check && doas make install`
  remains the final host-level acceptance test.
- PowerShell, MSBuild, and the .NET SDK were not installed. The scripts and
  project were statically reviewed and the project XML parsed, but the complete
  Windows package workflow was not executed by PowerShell/MSBuild here.
- PostgreSQL server/client binaries were unavailable, so no live database
  migration or database-backed browser test was run.
- Cross-built binaries used the repository's API-compatible offline dependency
  harness and are verification artifacts, not deployable release binaries.
  Production packages must be built from the pinned normal go.mod/go.sum graph.

INSTALLATION SAFETY PROPERTIES
- `make install` never rebuilds as root; it requires a previously built binary.
- `DESTDIR` staging never creates or changes host accounts.
- `/etc/wavecontrol/wavecontrol.env` is created automatically only when absent,
  is mode 0600, and is never overwritten during reinstall/upgrade.
- The canonical sample is installed separately as wavecontrol.env.example.
- Firmware, configuration backups, and the active environment file survive
  reinstall and uninstall workflows.
- Windows packaging creates wavecontrol.env automatically and `-KeepExisting`
  preserves the populated file and operator runtime data.
